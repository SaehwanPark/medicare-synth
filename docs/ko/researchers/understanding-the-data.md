# 데이터 이해하기

메디케어 연구 파일은 보통 **그 사람이 누구인지**, **자격이 있었는지**, **질환 표지**, **서비스·청구 사건**을 나눠 둡니다. Medicare-Synth의 예시와 시범 합성 세계도 그 모양을 따르므로, 분석 코드가 조인과 정의를 연습할 수 있습니다.

## 최소한의 관계

```text
수급자 (추출본에서 사람당 한 행)
    │
    ├── 자격 (시간에 따른 가입 / 연도 규칙)
    ├── 만성질환 표지 (예: 당뇨병, 심부전 플래그)
    └── 청구 / 이용 (사람당 0건, 1건, 또는 여러 건)
            └── 더 풍부한 예시에서는 청구 줄·상세 행이 있을 수 있음
```

| 개념 | 쉬운 뜻 |
| --- | --- |
| 한 행이 나타내는 것 | **단위**: 사람, 자격 구간, 청구, 또는 청구 줄 |
| 기록이 연결되는 방식 | 사람과 사건을 잇는 공유 식별자(키) |
| 행정 표지 | 코드나 알고리즘 결과. 임상의 의무기록 진단과 같지는 않음 |
| 청구가 있음 | 합성 추출본 안에서 사건이 있었음. 임상적 필요의 증거는 아님 |

## 건수가 달라지는 이유

- **환자 수 ≠ 청구 건수.** 입원한 사람 한 명이 생성 규칙과 예시 규칙에 따라 입원 행을 하나 또는 여러 개 낼 수 있습니다.
- 현재 시범 생성기에서 입원한 가상 수급자의 입원 청구는 **최대 한 건**입니다. 코드 시험에는 쓸모 있지만, 현실적인 재입원 궤적은 아닙니다.
- 질환 표지는 진단 코드가 붙은 입원 없이도 있을 수 있습니다. 시범의 결과는 모든 원인 입원의 여부이며, 당뇨병이 주진단인 입원이 아닙니다.

## 항목 정의는 어디에 있나

표 계열, 키, 원천에서 릴리스까지의 흐름은 개발자용 [데이터 모형 (영어)](../../../developers/data-model/)을 보세요. 출처 상태가 무엇을 증명하고 무엇을 증명하지 않는지는 [출처와 검증 (영어)](../../../developers/provenance-and-validation/)을 보세요.
